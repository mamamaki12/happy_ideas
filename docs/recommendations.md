## 選び方

次の4つの観点で5点満点をつけました。

| 観点 | 見ているところ |
|---|---|
| ニーズ | 調査で裏付けがあるか（市場規模・伸び・困りごとの深さ） |
| Web適性 | Webだけで製品にできるか（判定A/B/C）。「URLを開くだけ」の手軽さが活きるか |
| 差別化 | 既存アプリ（大手）に勝てる切り口があるか。ニッチで深いか |
| 続けやすさ | 毎日・毎週使う理由があるか。サーバー費用がかからないか |

## 1位の詳細: 推し活手帳（推し活ノート＋推しカメラ＋カウントダウン）

> ✅ **製品版を作りました** → [`products/oshi-techo/`](../products/oshi-techo/)（複数の推し・推し色テーマ・支出/予定の記録・フレームカメラ・年間まとめ画像・バックアップ。ホーム画面に追加して使えるPWA）

**なぜ1位か**
- 市場が大きい（約4兆円・約2,000万人）うえに、「記録したい」「写真に残したい（92.9%）」というニーズがはっきりしている
- 既存の推し活アプリは「支出」「記録」「カメラ」がバラバラ。**1つにまとめた手帳**はまだ少ない
- すべて判定A（Webだけで作れる）。サーバー費用ゼロで始められる
- 推し色・フレーム・「◯日後」の共有画像は、SNSで自然に広がる仕組みになる

**最初に足すとよい機能**
1. 3つの試作を1つのアプリに統合（推しごとにタブ）
2. 年間まとめ画像（Spotify Wrapped のような「推し活まとめ」）→ 年末にSNSで拡散
3. ライブ前日・当日の通知（ここだけ Push サーバーが必要）
4. 遠征の交通費・宿泊費の自動集計

**検証のしかた**: 推し活のSNSコミュニティで公開し、7日後も使っている人の割合（リテンション）を見る。

## 2位の詳細: 熱中症ガード

**なぜ2位か**
- 2026年は40℃以上の地点が7〜14か所の見込み。熱中症対策は「当日の警報」から「事前の計画」へ移っている
- 既存の天気アプリは「今の暑さ指数」を出すが、**「何時から何時なら外出しても大丈夫か」**を出すものは少ない
- 天気APIはキー不要（Open-Meteo）。ただし商用利用は有料プランになるので、気象庁データか有料APIへの切り替えが必要

**次に足すとよい機能**: 子どもの部活・高齢の家族向けの「見守りモード」、屋外作業の休憩計画、自治体のクーリングシェルター（涼み処）の地図。

## 作らない方がよいもの（試作で分かったこと）

| アプリ | 理由 |
|---|---|
| スマホ見た回数カウンター | Webでは他のアプリの使用を検知できない。自己申告では続かない |
| おさんぽ記録・寝言レコーダー | 画面を消すと止まる。ネイティブアプリ（またはスマホの標準機能）に勝てない |
| 指先カメラ心拍計 | iPhoneでライトを点けられない。精度も保証できない |
| QRコード読み取り | 標準カメラで十分。差別化は「危険URL警告」だけで、単体では弱い |

## 次のセッションでやること（提案）

1. **1位の推し活手帳を1つのアプリに統合**して、デザインを作り込む
2. GitHub Pages などで**HTTPS公開**し、実機（iPhone・Android）で確認する
3. Push 通知サーバーの最小構成（例: Cloudflare Workers + Web Push）を試し、判定Bのアプリを製品レベルにできるか検証する
