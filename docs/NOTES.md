## 2026-10-05 セッション1

### 依頼
- 市場を徹底的に調べ（セッションの約20%）、今ニーズがありそうなWebアプリのアイデアを**100個**出す
- カメラ・通知・位置情報などWebの機能を使い、**実装可能か確かめるために実際に作る**
- 動作確認・テスト・セキュリティチェックを入念に。UI/UXも改善する
- 確認なしで判断して進めてよい

### 判断したこと（確認なしで決めたもの）
| 判断 | 理由 |
|---|---|
| フレームワークなしの素のHTML/CSS/JS（ES Modules）にする | ビルド不要で、100個の試作を素早く量産できる。依存ライブラリがないのでサプライチェーンのリスクもない |
| 1アイデア = `apps/<slug>/` の1ディレクトリ | 個別に開ける・消せる・テストできる |
| 共通部品は `shared/lib.js` と `shared/style.css` | 見た目と安全対策（DOM組み立て・保存・通知など）を揃える |
| アイデアのデータは `ideas/ideas.js` に一元化 | ギャラリー・Markdown一覧・テストが同じデータを使う |
| `index.html` は `scripts/build.mjs` が生成する | CSPやヘッダーを全アプリで統一し、書き漏れを防ぐ |
| データは端末内（localStorage / IndexedDB）のみ、アカウントなし | 調査で見えた「課金疲れ」「プライバシー不安」への答えになる。サーバーも不要 |
| サーバーが必要なアイデア（共有アルバム・P2P通話など）は試作しない | 静的ホスティングの範囲で検証できるものを優先した |
| 外部APIは Open-Meteo（天気）のみ | APIキー不要・無料。CSPでそのアプリだけ許可する |

### セキュリティ方針
- すべてのページに CSP（`script-src 'self'`、`object-src 'none'`、`base-uri 'none'`、`form-action 'none'`）
- `innerHTML` を使わず、`h()` で DOM を組み立てる（ユーザー入力は常に textContent）
- インラインスクリプトとインラインイベントハンドラは使わない
- `scripts/security-check.mjs` で上記を機械的にチェックする
- 外部URLを開くときは `safeHttpUrl()` で `javascript:` などを弾く

### テスト方針
- `tests/unit/` … 計算ロジック（日付・割り勘・確率など）を `node --test` で検証
- `tests/e2e/smoke.spec.js` … 全試作を Playwright（スマホ幅のChromium、偽カメラ・偽マイク・位置情報は東京駅に固定）で開き、未捕捉エラー・横スクロール・ラベルのない入力欄・名前のないボタンがないことを確認
- `tests/e2e/apps.spec.js` … 主要アプリの操作テスト
