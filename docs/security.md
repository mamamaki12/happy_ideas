# セキュリティ方針とチェック結果

最終確認: 2026-11-05 ／ 対象: 試作100個 + ギャラリー + 製品版・暮らしのアプリ・サーバー機能

## 脅威モデル（何を守るか）

試作はすべて**静的ファイルだけ**で動き、サーバーもアカウントもありません。データは利用者の端末（localStorage / IndexedDB）にだけ保存されます。そのため主なリスクは次の3つです。

| リスク | 例 | 対策 |
|---|---|---|
| XSS（入力した文字がスクリプトとして動く） | 食品名に `<img onerror=…>` を入れる | DOM は `h()` で組み立て、文字は必ず `textContent`。`innerHTML` は全面禁止 |
| 外部から渡されるデータ | スタンプラリーのURL、QRコードの中身、CSVファイル | 形式チェック・長さ制限・件数制限。危険なURLは開く前に警告 |
| プライバシー（カメラ・マイク・位置情報） | 写真や位置が外部に送られる | 外部送信なし。天気APIには座標を小数点以下2〜3桁（約1km）に丸めて送るだけ |

## 実施している対策

### 1. Content Security Policy（全ページ）
```
default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data: blob:;
media-src 'self' blob: mediastream:; connect-src 'self'; worker-src 'self';
object-src 'none'; base-uri 'none'; form-action 'none'
```
- インラインスクリプト・`eval`・外部スクリプトは一切使えません
- `connect-src` は天気を使う2アプリだけ `https://api.open-meteo.com` を追加（最小権限）
- CSP は `scripts/build.mjs` が全ページに同じものを生成するので、書き漏れが起きません
- meta タグでは指定できない `frame-ancestors`・`Permissions-Policy` などは `_headers`（Netlify/Cloudflare Pages 用）で補います

### 2. 危険なAPIの禁止（静的チェック）
`npm run security`（`scripts/security-check.mjs`）が次を検出するとエラーになります。
- `innerHTML` / `outerHTML` への代入、`insertAdjacentHTML`、`eval`、`new Function`、`document.write`、文字列を渡す `setTimeout`
- HTML のインラインスクリプト・インラインイベントハンドラ（`onclick=` など）
- CSP の欠落、`unsafe-inline` / `unsafe-eval`
- `target="_blank"` に `rel="noopener"` がないリンク
- 外部スクリプト・外部モジュールの読み込み

### 3. 入力の扱い
| 箇所 | 対策 |
|---|---|
| QRコード読み取り | `javascript:` などは開かない。http・IPアドレス・国際化ドメイン（偽装の可能性）・短縮URL・ユーザー名入りURLを警告（`apps/qr-reader/logic.js`） |
| スタンプラリーのURL | Base64URL→JSON の解析失敗は拒否。タイトル40文字・地点50件まで。数値以外の座標や文字列以外の名前は除外（`apps/stamp-rally/logic.js`） |
| 座標・地図URLの貼り付け | 正規表現で数値だけ取り出し、緯度±90・経度±180の範囲外は拒否 |
| CSV読み込み（暗記カード） | 2MB・5000件まで |
| CSV書き出し（持ち物台帳） | 先頭が `= + - @` のセルは `'` を付けて、表計算ソフトで数式として実行されないようにする（CSVインジェクション対策） |
| GPX書き出し（おさんぽ） | XML の特殊文字をエスケープ |
| ICS書き出し（家族の予定） | RFC 5545 に従い `;` `,` `\` 改行 をエスケープ（改行による項目の注入を防ぐ） |
| URLで受け取るデータ（ほしいものリスト・家族の予定・トイレマップ） | 2万文字まで・Base64URL以外の文字は拒否。項目ごとに型・長さ・件数・座標範囲をチェック。商品URLは http(s) 以外を捨てる |
| GeoJSON の取り込み（ヒヤリハット地図） | 2MB・1000件まで。Point 以外・範囲外の座標・文字列以外の属性は捨てる |
| WebRTC で届くデータ（トランシーバー・写真交換） | チャットは500文字まで textContent で表示。写真は宣言したサイズ（5MBまで）を超えたら受信を中止し、MIMEタイプは画像だけ許可 |
| 電話リンク（緊急カード） | 数字だけを取り出して `tel:` に使う |

### 4. プライバシー
- カメラ・マイクはページを離れる（`pagehide`）と止める
- 写真から色だけ使うアプリ（空の色）は写真自体を保存しない
- 外部への fetch は `credentials: 'omit'`・`referrerPolicy: 'no-referrer'`
- 心拍計などは「医療機器ではない」ことを明示

## 集計API（ラリーメーカーの任意機能）

| 対策 | 内容 |
|---|---|
| 個人情報を持たない | 参加者の端末で作るランダムなIDと、開始・スタンプ・完走の種類だけ。位置情報は送らない |
| 主催者キー | 主催者の端末で作る48文字のランダムなキー。サーバーには SHA-256 だけを保存し、比較は定数時間 |
| ラリーIDの乗っ取り防止 | 既存のIDに別のキーで登録しようとすると 409 |
| 他サイトからの送信を拒否 | Origin ヘッダーが自サイトでなければ 403（水増し・CSRF対策） |
| 入力チェック | ID・端末ID・種類・番号を形式と範囲でチェック。本文は4KBまで、JSONのみ |
| SQLインジェクション対策 | すべてプレースホルダー（bind）。テストで注入を試して確認 |
| 水増しの上限 | 1ラリーあたり 5万件まで。同じ端末の重複は UNIQUE 制約で数えない。初めて見る端末（新しい参加者）は同じ回線から1日300台まで、新しいラリーの登録は1日20件まで（IPv6 は /64 ごと） |
| キャッシュしない | API の応答は `no-store`。Service Worker も `/api/` を扱わない（このテストで、古い集計がキャッシュされる不具合を発見して修正） |

## サーバー通知（推し活手帳の任意機能）

| 対策 | 内容 |
|---|---|
| 予定の中身を送らない | サーバーに送るのは「時刻」と「種類（入金/当落/予定）」だけ。通知の文面は固定。チケット名・推しの名前は端末から出ない（E2Eテストで送信データを検査） |
| SSRF対策 | サーバーが送信する先（購読の endpoint）を、既知の Push サービス（FCM・Mozilla・Apple・Windows）の https に限定。IPアドレス・localhost・ポート指定・似せたドメインは拒否 |
| 暗号化 | RFC 8291（aes128gcm）と RFC 8292（VAPID）を Web Crypto で実装し、**RFC の公開テストベクトルと完全一致**することをテストで確認 |
| 秘密鍵 | VAPID の秘密鍵はリポジトリに置かず、`wrangler secret` で登録 |
| 上限 | 1購読あたり予定50件・400日先まで。無効になった購読（404/410）は自動で削除。新しい購読は同じ回線から1日20件まで。Push サービスからの転送（3xx）はたどらない |
| Service Worker | 通知を押したときに開くURLは同じサイトの中だけ（外部URLはトップに置き換え）。題名80字・本文200字で切る |

## Claude API の中継（AIアプリ10個の任意機能）

詳しくは [`ai-apps.md`](./ai-apps.md) の「セキュリティとプライバシー」。要点:

- APIキーはサーバーの環境変数だけ。ブラウザ側のコードに `api.anthropic.com`・`x-api-key`・`sk-ant-` があると `npm run security` が失敗する
- 決まった10個の仕事だけを受け付け、システムプロンプト・モデル・`max_tokens` はクライアントから変えられない（`__proto__` などの名前も拒否）
- Origin チェック、任意のアクセスコード（定数時間比較）、IPごと・全体の1日の回数制限（IPは日ごとに変わるハッシュで保存）
- 利用者の文章は `<user_input>` で囲み、閉じタグを無害化。出力はツールの形に固定して、型・長さ・件数を検査してから返す
- 上流のエラー本文は返さない。入力・出力は保存しない

## てもとフォト（写真編集）

- ページの CSP を `connect-src 'none'` にして、写真や編集内容をどこにも送れないようにした（E2E で外部通信が0件であることを確認）
- 書き出しは Canvas から作り直すので Exif（位置情報・カメラ情報）は入らない（E2E で確認）。読み込んだ写真に位置情報があれば警告する
- Exif の解析は範囲チェックと循環検出つき（壊れたデータでのファズテスト）。プリセット・保存データは `validateState()` で検証
- 詳しくは [`photo-editor.md`](./photo-editor.md)

## 本番公開する場合の残課題
- HTTPS 必須（カメラ・マイク・位置情報・Service Worker の要件）
- 天気API（Open-Meteo）を商用で使う場合は利用規約に従い有料プランが必要
- 端末内保存なので、端末の紛失・ブラウザのデータ削除でデータは消える。必要ならエクスポート機能を追加する
- 共有サーバーが必要なアイデア（共有アルバムなど）を作る場合は、認証・レート制限・アップロード検査が別途必要

## ブランチ全体のセキュリティレビュー（最終）

サーバー側（`functions/api/rally/*`・`functions/api/push/*`・`server/push/*`）と `sw.js` の push 処理、URLハッシュの読み込みを見直し、**確度の高い脆弱性は見つかりませんでした**。確認した点:

- SQL はすべてプレースホルダー。入力は正規表現・型・件数・4KBで制限
- Push の送り先は既知の Push サービスのホストだけ（SSRF 対策）。通知の文面は種類ごとに固定で、利用者の入力は送らない
- 主催者キーはハッシュだけ保存し、定数時間で比較。既存のラリーIDは別のキーで上書きできない
- Service Worker の通知クリックは同じオリジンの URL だけ開く
- 残るリスク（許容）: 参加イベントの水増し（端末IDは自己申告）、Push 購読の endpoint を知っている人による解除。→ 2026-11-05 に回線ごとの上限を追加（下記）

## 2026-11-05 の見直し（2回目）

前回の「確度の高い脆弱性なし」をうのみにせず、サーバー側・Service Worker・製品版を見直しました。見つけたものはすべて直し、テストを追加しています。

| 見つけた問題 | 重さ | 何ができたか | 直したこと | テスト |

| AI の1日の回数制限が IPv6 で効かない | 中 | IPv6 のスマホや家庭の回線は /64（アドレスの後ろ半分を自由に変えられる範囲）を持つので、アドレスを変えるだけで「IPごと20回」を何回でも抜けられた。全体の上限（1日1000回）まで1人で使い切れる＝費用の上限まで使われ、ほかの人は使えなくなる | IPv6 は /64 ごとに数える（`server/limits.js`）。数える単位は Cloudflare が付ける CF-Connecting-IP だけ（X-Forwarded-For は利用者が書き換えられるので使わない） | `ai-proxy.test.js`・`limits.test.js` |

確認したが問題がなかったもの: SQL はすべてプレースホルダー、主催者キー・アクセスコードの比較は定数時間、Push の送り先のホスト制限（似せたドメイン・ポート・IP を拒否）、通知を押したときに開くURLは同じサイトだけ、AI の出力はすべて文字として表示、上流のエラー本文は返さない、CORS ヘッダーなし（他サイトのページから読めない）＋Origin チェック、GitHub Actions は `contents: read`・`pull_request_target` なし・`run:` に外から入る値なし、`npm audit --omit=dev` 0件、コミット履歴に秘密の値なし。

残るリスク:
- 回線ごとの上限は、たくさんの回線（IPv6 の大きな範囲など）を持つ人には抜けられる。全体の上限（AI は1日の回数、ラリーは1ラリー5万件）と Anthropic Console の月の上限が最後の守り
- GitHub Pages では、同じ人のほかのアプリ（`<ユーザー名>.github.io/別のリポジトリ/`）と、端末内の保存場所（localStorage など）も共有する。ほかのアプリに XSS があると、このアプリの記録も読まれうる。気になる場合は独自ドメインや Cloudflare Pages など、アプリごとに別のドメインで公開する
