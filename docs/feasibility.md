# Webの機能ごとの実現性レポート

100個の試作を作って分かった、「Webアプリでどこまでできるか」のまとめです。試作ごとの判定は [`feasibility-apps.md`](./feasibility-apps.md) を参照してください。

- 検証方法: スマホ幅（390×844）の Chromium と Playwright で全試作を自動テスト（偽カメラ・偽マイク・位置情報の固定・センサーイベントの送出・音声認識の差し替え）
- iOS Safari の挙動: 公式ドキュメントと既知の仕様に基づいて記載（実機では未確認。下の「実機で確かめること」を参照）

## 結論（先に要点）

1. **「開いて使う」アプリはWebで十分。** 記録・計算・カメラ撮影・音声読み上げ・位置の取得は、iPhone を含めてほぼ全部動く。100個中60個が「Webだけで製品にできる（A）」。
2. **最大の壁は「決まった時刻の通知」。** リマインダー系（お薬・ゴミの日・期限通知・誕生日など）は、ページを閉じると通知が届かない。確実に届けるには **Push サーバー**が必要で、iPhone は **ホーム画面に追加**した場合だけ受け取れる。
3. **画面を消すと止まるものはネイティブ向き。** 散歩の記録、寝言の録音、スマホを見た回数の計測などは、Webでは画面を点けたままにする必要がある。
4. **「サーバーが必要」と思っていたものの一部は、なくても動く。** URLのハッシュにデータを入れて配る（スタンプラリー・ほしいものリスト・トイレマップ・家族の予定）、WebRTC の接続コードを手で交換する（トランシーバー・写真交換）ことで、サーバーなしで成立した。
5. **Android の Chrome だけの機能に頼らない。** バーコード読み取り（BarcodeDetector）、ライトの点灯、振動、バッテリー残量は iPhone で使えない。代替手段（ライブラリ・画面表示・手入力）を必ず用意する。

## 機能ごとの結果

| 機能 | 使った試作 | 結果 | iPhone（Safari） | 注意点・回避策 |
|---|---|---|---|---|
| カメラ（getUserMedia） | レシート家計簿、推しカメラ、書類スキャン など11個 | ✅ 動く | ✅ | `playsinline` が必須。HTTPSが必須。起動前に撮影ボタンを押される競合に注意（推しカメラで実際に不具合が出て修正） |
| 写真ファイル選択（`<input type=file capture>`） | カメラ系すべて | ✅ | ✅ | カメラ許可を拒否された場合の代替として常に用意した |
| ライト（torch） | 心拍計、SOSライト | △ | ❌ | Android の Chrome だけ。iPhoneは画面の白いフラッシュで代用 |
| バーコード・QR（BarcodeDetector） | 冷蔵庫番、QR読み取り | △ | ❌ | Android Chrome のみ。製品化するなら zxing-wasm 等が必要 |
| 位置情報（Geolocation） | 駐車位置、スタンプラリー、熱中症ガード など11個 | ✅ | ✅ | 画面を消すと `watchPosition` が止まる。ジオフェンス（近づいたら通知）はWebにない |
| 方位（コンパス） | 駐車位置、避難場所コンパス | △ | ✅（許可が必要） | iOSは `webkitCompassHeading`、Androidは `deviceorientationabsolute`。iOS 13以降はユーザー操作で `requestPermission()` が必要 |
| 傾き・加速度センサー | 水平器、揺れ計、スマホ伏せ、ルーレット | ✅ | ✅（許可が必要） | センサーのない端末は `beta=null` の空イベントを送ってくる。無視しないと誤動作する（スマホ伏せで実際に発生し修正） |
| 通知（Notification） | お薬、ゴミの日、目の休憩 など14個 | △ | △ | **ページを開いている間だけ**確実。閉じた後の通知には Push API とサーバーが必要。iPhoneはホーム画面追加が前提 |
| 画面スリープ防止（Wake Lock） | 集中タイマー、おさんぽ、SOS など12個 | ✅ | ✅（16.4以降） | タブを切り替えると解除されるので、戻ったときに取り直す処理を共通部品に入れた |
| マイク（Web Audio） | 騒音メーター、音程チェッカー | ✅ | ✅ | 端末ごとにマイク感度が違うので dB は目安。`echoCancellation` などをオフにしないと音量が勝手に変わる |
| 録音（MediaRecorder） | 声の手紙、寝言レコーダー、シャドーイング | ✅ | ✅ | 形式が違う（Chrome は webm、iPhone は mp4）。`isTypeSupported()` で選ぶ |
| 音声の合成（Web Audio） | 環境音、リズムタップ、ブザー | ✅ | ✅ | AudioContext は操作直後なら最初から「再生中」状態。自前で状態を持たないと最初のタップで止まる（環境音で実際に発生し修正） |
| 音声認識（Web Speech） | 声でToDo、発音チェック、話すスピード | △ | ✅ | Chrome はネット経由（オフラインでは使えない）。Firefox は非対応。連続認識は無音で切れるので自動再開が必要 |
| 音声読み上げ（speechSynthesis） | 指さし会話帳、読み聞かせ、ストレッチ | ✅ | ✅ | 声の種類と自然さは端末次第 |
| 共有（Web Share） | 割り勘、げんきボタン、カード系 など | ✅ | ✅ | ファイル共有はデスクトップで非対応のことがある → ダウンロードで代替 |
| 振動（Vibration） | 多数 | △ | ❌ | iPhoneは無視される。振動だけに頼る通知は不可 |
| 全画面（Fullscreen） | ペンライト、応援ボード | △ | ❌（iPhone） | iPhoneのSafariは動画以外の全画面に非対応 → 画面全体を覆う表示で代用 |
| 画面の向き固定 | 応援ボード | △ | ❌ | Android の全画面時のみ |
| バッテリー残量 | 停電モード | △ | ❌ | Chrome系のみ |
| 端末内保存（localStorage / IndexedDB） | ほぼ全部 | ✅ | ✅ | 写真は IndexedDB に Blob で保存。iOSはしばらく使わないとデータが消えることがある → ホーム画面追加で軽減 |
| オフライン（Service Worker） | 全部 | ✅ | ✅ | 一度開いたページはオフラインでも開ける |
| 外部API（fetch） | 熱中症ガード、洗濯タイマー | ✅ | ✅ | Open-Meteo はAPIキー不要。CSPで許可するのは使うアプリだけ |
| ページの表示状態（visibilitychange） | 集中タイマー、スマホ見た回数 | ✅ | ✅ | 「他のアプリを開いた」ことは分かるが、**何をしていたかは分からない** |
| WebRTC（サーバーなし） | P2Pトランシーバー、その場で写真交換 | ✅ | ✅ | 接続コード（SDP）を手で交換すれば、シグナリングサーバーなしでつながる（2タブ間で自動テスト済み）。TURNがないと携帯回線同士などでつながらないことがある |
| URLにデータを入れて共有 | スタンプラリー、ほしいものリスト、家族の予定、トイレマップ | ✅ | ✅ | Base64URL で数KBまで。受け取る側はアプリ不要。改ざんされても安全なように、読み込み時に形式・長さ・件数をチェック |
| 端末内AI（Summarizer API） | ブラウザ内要約 | △ | ❌ | デスクトップの Chrome の一部のみ。使えない環境では自前の抽出型要約に切り替える |
| Canvas での画像生成 | 推しカメラ、棚、カード、空の色 | ✅ | ✅ | 日本語の折り返しは自前実装（句読点の行頭禁止） |
| 手書き（Pointer Events） | なぞり書き | ✅ | ✅ | `touch-action: none` が必須 |

## 「サーバーを足せば化ける」アイデア

> ✅ 推し活手帳に **Web Push のサーバー通知（ベータ）** を実装しました（Cloudflare Workers の Cron + D1）。予定の中身はサーバーに送らず、時刻と種類だけを送ります。暗号化は RFC 8291 のテストベクトルで検証済み。実際の Push サービス（FCM・Apple）への送信は、公開後の実機確認が必要です。

判定 B の多くは、**Push 通知サーバー**か**データ同期**を足せば製品になります。

| 足すもの | 効果があるアイデア |
|---|---|
| Web Push（例: 自前サーバー + VAPID、または Firebase Cloud Messaging） | お薬リマインダー、ゴミの日、サブスク棚卸し、推しカウントダウン、誕生日、ポイント期限、いまの瞬間カメラ |
| データ同期（例: Supabase / Firebase） | 値段おぼえ帳（家族で共有）、育児記録（夫婦で共有）、介護ノート（家族・ケアマネと共有）、毎日げんきボタン（押し忘れを自動で家族に通知） |
| バーコード/OCR ライブラリ（WASM） | 冷蔵庫番（iPhone対応）、レシート家計簿（金額の自動読み取り） |

## 実機で確かめること（このセッションではできなかったこと）

- iPhone の Safari で、ホーム画面に追加したときの Push 通知の受信
- iPhone のコンパス方位（`webkitCompassHeading`）の精度
- Android 実機でのライト点灯と BarcodeDetector の読み取り速度
- 画面を消したときに録音・位置情報・タイマーがどこまで続くか（端末ごとの差）
- 実際の歌声での音程検出、実際の指での心拍推定の精度
